# Note Workstation v1.0 — 落地总览

> **规格来源：** [`../Note-Workstation-开发文档-v1.0.md`](../Note-Workstation-开发文档-v1.0.md)  
> **用法：** 按阶段顺序执行；每阶段结束必须通过「验收」再进入下一阶段。  
> **For agentic workers：** 推荐按阶段打开对应计划，用 subagent-driven-development 或 executing-plans 逐 Task 执行。

## 目标

交付可安装的桌面应用：本地 Markdown 笔记 + Git 版本 + Gitee 同步（带 Token HTTPS 地址可直接用）。

## 技术栈（锁定）

Tauri 2.0+ · Vue 3.4+ · TypeScript 5.3+ · Pinia · Vite 5 · marked · highlight.js · DOMPurify · Rust 1.75+ · git2 · reqwest · tokio

## 全局约束（所有阶段默认遵守）

| 约束 | 值 |
|------|-----|
| 命名 | Vue PascalCase；TS kebab-case；Rust snake_case；命令 snake_case |
| IPC 序列化 | `#[serde(rename_all = "camelCase")]` |
| 错误 | 统一 `AppError { code, message }` / `AppResult<T>` |
| 持久化 | 仅 `tauri-plugin-store`（Token、最近工作区、主题等） |
| Token 远程 | `https://oauth2:<TOKEN>@gitee.com/<owner>/<repo>.git` |
| v1.0 不做 | 实时协作、移动端、WYSIWYG、分支切换、discard、自建后端 |
| 提交规范 | Conventional Commits；测试/文档默认不 git add（除非明确要求） |

## 文件职责总表（锁定）

### Rust（`src-tauri/src/`）

| 文件 | 职责 |
|------|------|
| `main.rs` / `lib.rs` | 启动、插件、注册 commands |
| `error.rs` | `AppError` / `AppResult` |
| `config.rs` | store 键名常量、读写封装（可选薄层） |
| `commands/fs_ops.rs` | 扫描、读写、增删改、搜索 |
| `commands/git_ops.rs` | init/status/commit/log/clone/push/pull |
| `commands/gitee_ops.rs` | user/repos/create/`build_auth_url` |
| `capabilities/default.json` | 最小权限 |
| `tauri.conf.json` | 窗口、CSP、产品名 |

### Vue（`src/`）

| 文件 | 职责 |
|------|------|
| `api/tauri.ts` | 全部 `invoke` 封装 |
| `types/index.ts` | 与后端一致的 TS 类型 |
| `stores/workspace.ts` | 工作区 / 树 / 当前文件 |
| `stores/editor.ts` | 内容 / 模式 / 保存 |
| `stores/git.ts` | Git 状态 |
| `stores/settings.ts` | Token / 主题 / 最近路径 |
| `stores/toast.ts` | Toast（可并入 settings，建议独立） |
| `components/**` | 布局、树、编辑器、预览、Git/Gitee 面板、搜索、设置 |
| `utils/markdown.ts` / `debounce.ts` | 渲染与防抖 |

## 每阶段完成定义（DoD）

1. 本阶段验收清单全部勾选  
2. 相关 `cargo test` / Vitest（若本阶段有）通过  
3. `pnpm tauri dev` 可手动走通本阶段主路径  
4. 不引入 v1.0 明确不做的功能
